# 30분 핵심 코스 — 과제 제출 확인을 한 번에, 그리고 내 명령으로

- ⏱ 약 30분
- 준비: 클로드 코드 설치·로그인 완료, 이 폴더(`claude-lab`)에서 `claude` 실행
- 실습 폴더: `practice/04-submissions` (실습 4와 같은 재료)
  - `roster.csv`: 가상 수강생 30명 (학생01~학생30)
  - `submissions/`: 과제1 제출 파일 27개 (파일 이름이 제각각)
- 정답 기준: `tutor/answer-keys/lab04.md` (실습 도우미 전용)
- 이번 코스를 마치면 교수님 업무 하나를 처음부터 끝까지 맡겨 봅니다.
  - **작업실 확인**: 클로드가 일할 폴더를 정하고 확인합니다.
  - **백업 → 계획 → 실행 → 검증**: 실제 업무 흐름 그대로 해 봅니다.
  - **허락 화면과 작업 모드**: 무엇을 승인하고 무엇을 거절할지 교수님이 정합니다.
  - **나만의 명령(스킬)**: 방금 한 일을 `/submission-check` 한 마디로 다시 쓸 수 있게 저장합니다.

> **교수님 업무**: 마감 후 제출 파일을 하나씩 열어 누가 냈는지, 늦었는지 확인하기
> **자동화 후**: 요청 한 번 → 파일 이름 통일 + 현황표 + 확인 필요 목록 → 교수님은 **검증과 판단**만

> ⚠ 반드시 가상 학생 자료로 연습합니다. 실제 학생 이름·학번·성적을 AI에 넣기 전에는 소속 대학의 AI 활용 지침과 개인정보 규정을 먼저 확인해 주세요.

**뼈대: ① 작업실 확인 → ② 백업 → ③ 계획 → ④ 실행 → ⑤ 검증 → ⑥ 명령으로 저장**
클로드 코드는 ④를 빠르게 해 줍니다. 나머지는 교수님의 판단입니다.

### STEP 1/8 — 작업실 확인과 작업 모드 (⏱ 3분)

🎯 왜 하나요?
클로드는 `claude`를 실행한 그 폴더 안의 파일을 **실제로** 바꿉니다. 조교에게 "연구실 3번 책장만 정리해 줘" 하고 방을 정해 주는 것과 같습니다. 그래서 일을 맡기기 전에 ① 어느 방인지, ② 어떤 방식으로 일하게 할지를 먼저 정합니다.

👉 이렇게 해 보세요
1. 입력 칸 맨 앞에 `!`를 붙이면 클로드에게 묻지 않고 터미널 명령을 바로 실행합니다. 지금 위치를 확인하세요.
```
! pwd
```
2. `Shift + Tab`을 한 번씩 누르며 화면 아래 상태 표시줄이 바뀌는 것을 보세요.

| 표시 | 뜻 | 언제? |
|---|---|---|
| (표시 없음) 기본 | 파일을 바꿀 때마다 허락을 구함 | **처음엔 늘 이것** |
| accept edits on | 파일 편집은 묻지 않고 진행 | 익숙하고 백업이 있을 때 |
| plan mode on | 파일을 건드리지 않고 계획만 보여 줌 | 큰 작업 전에 (STEP 3) |

3. 마지막에는 **기본 모드(표시 없음)**로 돌려 두세요.

✅ 성공 기준: `pwd` 결과의 끝이 실습 폴더 이름(`claude-lab`)이고, 세 가지 모드를 본 뒤 기본 모드로 돌려 두었다.

💡 힌트
- `pwd` = "지금 어느 방(폴더)에 있지?"
- 경로 끝이 실습 폴더가 아니라면: `/exit`로 나간 뒤 `cd ~/claude-lab` → `claude`로 다시 실행하세요.
- 모드 문구는 버전마다 조금 다를 수 있습니다. 세 번 누르면 한 바퀴 돌아옵니다.
- 클로드가 엉뚱하게 길게 일하면 **Esc** 한 번으로 언제든 멈출 수 있습니다.

### STEP 2/8 — [직접] 재료 보기와 백업 (⏱ 3분)

🎯 왜 하나요?
클로드가 바꾼 파일 내용은 `/rewind`로 되돌릴 수 있지만, 파일 **이동·이름 바꾸기**는 완전히 되돌리지 못할 수 있습니다. 그래서 백업은 도구에 맡기지 않고 교수님 손으로 합니다.

👉 이렇게 해 보세요
1. 제출 폴더를 열어 파일 이름을 훑어보세요.
   - Windows:
```
! explorer "practice\04-submissions\submissions"
```
   - Mac:
```
! open practice/04-submissions/submissions
```
2. 폴더를 통째로 복사해 백업합니다. (Windows·Mac 같은 명령)
```
! cp -R practice/04-submissions/submissions practice/04-submissions/submissions-backup
```
3. 백업이 생겼는지 확인합니다.
```
! ls practice/04-submissions
```

✅ 성공 기준: `practice/04-submissions` 안에 `submissions-backup` 폴더가 생겼다.

💡 힌트
- `!`로 **내가 직접 친 명령**은 클로드의 판단을 거치지 않습니다. 백업처럼 중요한 일은 내 손으로.
- 명령 사이 띄어쓰기 한 칸도 중요합니다. 코드블록 안의 문장을 그대로 복사해 붙여 넣으세요.
- `! cp`가 안 되면: `/exit` → 터미널에서 같은 명령(`!` 없이) → `claude -c` (하던 대화 이어서 켜기)

### STEP 3/8 — 계획 모드로 계획 먼저 보기 (⏱ 5분)

🎯 왜 하나요?
큰 일을 맡기기 전에 **어떻게 할지부터** 보고, 마음에 들 때만 실행하게 합니다. 계획 모드에서는 클로드가 파일을 읽기만 합니다.

👉 이렇게 해 보세요
1. `Shift + Tab`으로 화면 아래가 **plan mode on**이 되게 합니다.
2. 아래 요청을 복사해서 붙여 넣으세요.
```
practice/04-submissions 의 과제1 제출물을 roster.csv 와 대조해서 정리하려고 해. 실행하지 말고 계획만 보여줘.
- submissions 폴더 안 파일 이름을 '학번_이름_과제1.txt' 로 통일
- 파일 이름에 학번이 없으면 파일 내용에서 학번을 찾아 판단
- 파일 이름과 내용의 학생 정보가 다르면 이름을 바꾸지 말고 '확인 필요' 목록에 넣기
- 같은 학생이 여러 번 냈으면 지우지 말고 둘 다 남기고 _1, _2 로 표시
- practice/04-submissions/submission-status.csv 만들기
  열: 학번, 이름, 제출여부, 제출일시, 지각여부, 파일명, 비고
  엑셀에서 한글이 깨지지 않게 UTF-8 (BOM) 으로 저장
- 마감: 2026-10-20 23:59 (23:59 제출은 정시로 본다)
```

✅ 성공 기준: 클로드가 파일을 바꾸지 않고 계획을 보여 주었다.

💡 힌트
- "23:59 제출은 정시로 본다"처럼 **경계를 미리 정해 주는 것**이 규칙을 잘 쓰는 요령입니다.
- 요청 맨 앞에 `/plan`을 붙여도 계획 모드로 요청할 수 있습니다.

### STEP 4/8 — [직접] 계획 검토하고 한 번 고치기 (⏱ 3분)

🎯 왜 하나요?
실행 전 몇 분의 검토가 사고를 막습니다. **무엇을 기준으로 처리할지는 사람이 정합니다.**

👉 이렇게 해 보세요
계획을 읽으며 점검하세요.
- □ 학번을 어떻게 찾는지(파일 이름 / 내용) 설명이 있나요?
- □ **삭제** 작업이 들어 있지 않나요?
- □ 애매한 경우를 **스스로 결정하지 않고** 교수님께 넘기나요?
- □ 미제출자도 표에 들어가나요? (명단 30명 전체가 표에 있어야 합니다)

고칠 점은 말로 그대로 하시면 됩니다. **최소 한 번은 고쳐 보세요.** 예)
```
비고 열에 '확인 필요' 사유를 한 줄로 적어줘. 그리고 지각한 학생은 몇 분 늦었는지도 비고에 넣어줘.
```

✅ 성공 기준: 계획을 읽고 체크리스트를 확인했으며, 한 번 이상 고쳐 달라고 요청했다.

💡 힌트
- 계획에 미제출자가 빠져 있다면 "명단 30명 전원을 표에 넣고 미제출자는 제출여부를 N으로"라고 덧붙여 보세요.
- 계획이 다시 나옵니다. 마음에 들 때까지 반복해도 됩니다.

### STEP 5/8 — 실행: 허락 화면 읽으며 진행 (⏱ 5분)

🎯 왜 하나요?
**결정권은 교수님께 있습니다.** 허락 화면을 읽는 그 몇 초가 판단 근육을 쓰는 시간입니다.

👉 이렇게 해 보세요
1. 계획이 마음에 들면 클로드가 진행 방법을 묻습니다. 처음에는 **편집마다 직접 확인하며 진행**하는 쪽을 고르세요. (문구 예: "Yes, and manually approve edits")
2. 허락 화면이 나오면 어떤 명령인지 읽고 승인합니다. 보통 세 가지 선택지가 있습니다: ① 예 ② 이번 세션 동안 묻지 않기 ③ 아니오(다르게 해 달라고 말하기)
3. ⚠ `rm`, `del`, `Remove-Item` (삭제 명령)이 보이면 **아니오**를 고르고 이렇게 말하세요.
```
삭제하지 말고, 이름만 바꾸거나 그대로 남겨줘
```
4. 불안하면 **Esc**로 멈추고 물어보세요.
```
지금까지 바꾼 파일을 표로 보여줘
```

✅ 성공 기준: `submission-status.csv`가 생겼고, `submissions` 안 파일 이름이 대부분 `학번_이름_과제1.txt` 모양이 되었다.

💡 힌트
- 이름 바꾸기 명령이 여러 번 반복됩니다. 같은 종류가 계속 나와 번거로우면 ②를 골라도 됩니다. 단, **이름 바꾸기(이동) 명령인지 꼭 확인한 다음에.**
- 계획 모드에서 기본 모드로 바꾸라는 안내가 나오면 따라 주세요.

### STEP 6/8 — [직접] 검증: 숫자로, 그리고 눈으로 (⏱ 5분)

🎯 왜 하나요?
"만들었습니다"라는 말보다 **파일을 직접 여는 것**이 확인입니다. AI는 그럴듯하게 틀릴 수 있습니다.

👉 이렇게 해 보세요
1. 현황표를 엑셀로 엽니다.
   - Windows:
```
! start practice/04-submissions/submission-status.csv
```
   - Mac:
```
! open practice/04-submissions/submission-status.csv
```
2. 직접 세어 보세요.
   - □ 제출 + 미제출 = **30명**인가요?
   - □ 지각으로 표시된 학생은 몇 명인가요? 제출일시를 보고 맞는지 확인
   - □ 마감 정각(23:59)에 낸 학생은 어떻게 표시되었나요?
   - □ 두 번 낸 학생이 표시되었나요?
   - □ '확인 필요'로 넘어온 파일이 있나요? 그 파일을 직접 열어 보세요.
3. 다 보셨으면 실습 도우미에게 한 번 더 확인을 맡기세요.
```
확인해 주세요
```

✅ 성공 기준: 교수님이 표를 직접 열어 위 항목을 확인했고, 실습 도우미의 확인도 받았다.

💡 힌트
- 엑셀에서 한글이 깨지면: "submission-status.csv 를 UTF-8 BOM 으로 다시 저장해줘"
- 엑셀이 없으면 메모장으로 열어도 됩니다: `! start notepad practice/04-submissions/submission-status.csv` (Mac: `! open -e ...`)
- 클로드의 판단이 틀린 곳을 찾으셨다면 그것이 오늘의 수확입니다.

### STEP 7/8 — 방금 한 일을 나만의 명령으로 저장하기 (⏱ 5분)

🎯 왜 하나요?
다음 과제 때 이 긴 요청을 다시 쓰지 않도록, 조교에게 **업무 절차서**를 한 번 써 두는 것입니다. 이것을 **스킬**이라고 하며, `/명령이름` 한 마디로 부를 수 있습니다. 지금 쓰시는 `/hint`, `/next`도 이 폴더에 들어 있는 스킬입니다.

👉 이렇게 해 보세요
1. 기본 모드인지 확인한 뒤(STEP 1 표), 아래 요청을 붙여 넣으세요.
```
지금까지 한 과제 제출 확인 작업을 스킬로 만들어줘.
위치: .claude/skills/submission-check/SKILL.md
이름: submission-check
하는 일: 내가 과제 이름을 주면(예: /submission-check 과제2)
  practice/04-submissions 의 제출물을 roster.csv 와 대조해서
  오늘 쓴 규칙 그대로 파일 이름을 통일하고 현황표 CSV 를 만든다.
  마감 일시는 매번 나에게 물어본다.
  시작 전에 백업 여부를 묻고, 실행 전에 계획부터 보여 준다.
  파일은 절대 삭제하지 않는다. 애매한 것은 스스로 정하지 말고 '확인 필요'로 남긴다.
```
2. [직접] 만들어진 스킬 파일을 열어 읽어 보세요.
   - Windows:
```
! start notepad .claude/skills/submission-check/SKILL.md
```
   - Mac:
```
! open -e .claude/skills/submission-check/SKILL.md
```
   - □ 내가 말한 규칙이 다 들어 있나요?
   - □ 내가 말하지 않은 규칙이 추가되어 있나요? 그 규칙에 동의하나요?
3. 입력 칸에 `/sub`까지 쳐서 목록에 `/submission-check`가 보이는지 확인하세요.

✅ 성공 기준: `.claude/skills/submission-check/SKILL.md` 파일이 생겼고, 교수님이 직접 읽어 보았으며, `/` 목록에서 명령을 찾았다.

💡 힌트
- 스킬 파일은 프로그래밍 언어가 아니라 **우리말로 쓴 업무 절차서**입니다. 메모장으로 직접 고쳐도 됩니다.
- 파일 안의 `$ARGUMENTS`라는 글자 자리에 `/submission-check 과제2`의 `과제2`가 들어갑니다.
- 목록에 안 보이면: `/exit` → `claude -c`로 다시 켜 보세요. (새 스킬을 다시 읽어 옵니다)
- 스킬을 이 폴더(`.claude/skills/`)에 두면 이 폴더에서만, 홈 폴더의 `~/.claude/skills/`에 두면 어느 폴더에서든 쓸 수 있습니다.

### STEP 8/8 — 🏋️ 근육 체크 (⏱ 1분)

👉 [직접] 하나씩 여쭤봅니다.
1. 클로드가 **스스로 정해 버렸으면 곤란했을** 판단은 무엇이었나요?
2. 내 업무 중 다음으로 스킬로 만들고 싶은 것 하나와, 거기에 꼭 넣을 **안전 규칙 한 줄**은?

> 자동화해도 사람이 꼭 확인할 일: 지각 인정 여부, 예외 사정. 자동화하지 않을 일: 학생에 대한 최종 판단.

📝 30분 코스 정리
| 입력 | 뜻 |
|---|---|
| `! 명령` | 터미널 명령을 바로 실행 (`! pwd`, `! cp -R ...`) |
| `Shift + Tab` | 작업 모드 바꾸기 (기본 / 편집 자동 / 계획) |
| Esc | 지금 하던 일 멈추기 |
| 허락 화면 ③ 아니오 | 거절하고 "대신 이렇게 해 줘"로 방향 바꾸기 |
